# oauth2-proxy (Zitadel authentication gateway)

Browser authentication gateway for selected Traefik-routed UIs. Backed by Zitadel
OIDC; opt-in per UI via `AUTH_ENABLED` / `AUTH_MIDDLEWARE` on the target service.

## Quick Start

```sh
# From repo root
make setup                       # Creates oauth2-proxy/.env; fills cookie secret
make up service=postgres         # Zitadel DB dependency
make up service=traefik
make up service=zitadel
# Register a Zitadel app (see below), then set CLIENT_ID / CLIENT_SECRET in .env
make up service=oauth2-proxy
```

| Resource                | URL                                          |
| ----------------------- | -------------------------------------------- |
| Sign-in / callback host | `https://auth.dss.localhost`                 |
| OAuth callback          | `https://auth.dss.localhost/oauth2/callback` |
| Local gateway logout    | `https://auth.dss.localhost/oauth2/sign_out` |

No host ports are published; access is Traefik-only (`*.dss.localhost` cert covers `auth`).

## Zitadel application registration

1. Open [Zitadel Console](https://zitadel.dss.localhost/ui/console).
1. Create a **Project** (or reuse an existing one) → **New Application**.
1. Type: **Web** → **Code** (authorization code + PKCE).
1. Redirect URI: `https://auth.dss.localhost/oauth2/callback`
1. Post-logout / additional origins (optional): `https://auth.dss.localhost`
1. Copy **Client ID** and **Client Secret** into `oauth2-proxy/.env`:
   ```env
   OAUTH2_PROXY_CLIENT_ID=...
   OAUTH2_PROXY_CLIENT_SECRET=...
   ```
1. Restart: `make restart service=oauth2-proxy`

Issuer discovery: `https://zitadel.dss.localhost/.well-known/openid-configuration`.

## Traefik middleware

Defined on this service (Docker provider):

| Middleware     | Purpose                                                                       |
| -------------- | ----------------------------------------------------------------------------- |
| `auth-none`    | No-op (public UI; default for opt-in services)                                |
| `auth-default` | Require any authenticated Zitadel user (ForwardAuth with browser redirect)    |
| `auth-admin`   | Extension point for stricter policies (same forward auth until customized)    |
| `auth-forward` | ForwardAuth to oauth2-proxy `/` (202 authenticated, 302 to sign-in otherwise) |

Protect a UI by setting in that service’s `.env` and restarting it:

```env
AUTH_ENABLED=true
AUTH_MIDDLEWARE=auth-default
```

Use `AUTH_MIDDLEWARE=auth-none` (default) to keep the UI public. Do **not** attach
these middlewares to Zitadel itself.

Forwarded identity headers (when authenticated): `X-Auth-Request-User`,
`X-Auth-Request-Email`, `X-Auth-Request-Access-Token`, `Authorization`.

OAuth callback and proxy health paths on `auth.dss.localhost` are served by this
container directly (no ForwardAuth on the oauth2-proxy router).

### Logout behavior

Use `/oauth2/sign_out` to clear the oauth2-proxy browser session. To return to
Mermaid after logout, the endpoint accepts an encoded `rd` parameter, for
example:

```text
https://auth.dss.localhost/oauth2/sign_out?rd=https%3A%2F%2Fmermaid.dss.localhost
```

This local logout does not terminate the user's Zitadel SSO session. For a
complete one-step logout, set `rd` to Zitadel's OIDC end-session endpoint.
oauth2-proxy replaces the `{id_token}` placeholder before redirecting:

```text
https://auth.dss.localhost/oauth2/sign_out?rd=https%3A%2F%2Fzitadel.dss.localhost%2Foidc%2Fv1%2Fend_session%3Fid_token_hint%3D%7Bid_token%7D%26post_logout_redirect_uri%3Dhttps%3A%2F%2Fmermaid.dss.localhost
```

The `post_logout_redirect_uri` must be registered in the Zitadel application.
Do not put ForwardAuth on these gateway or Zitadel logout routes.

## Cookie / session

- Cookie domain: `.dss.localhost` (shared across UI subdomains)
- Secure + SameSite=Lax for HTTPS local certs
- Default gateway session expiry: `8h` (`OAUTH2_PROXY_COOKIE_EXPIRE`)
- Cookie refresh is disabled by default (`OAUTH2_PROXY_COOKIE_REFRESH=0`)
- `OAUTH2_PROXY_COOKIE_SECRET` is auto-generated by `make setup` when empty;
  Zitadel client credentials stay manual

Traefik v2.11 ForwardAuth cannot copy oauth2-proxy's refreshed cookie into the
browser response, so enabling cookie refresh would repeatedly refresh the
session without persisting the result. Keep it disabled unless the proxy path
is upgraded or otherwise configured to return oauth2-proxy's `Set-Cookie`
header. A refresh flow also requires the Zitadel `offline_access` scope.

Session expiry is a safety limit, not a logout mechanism. Do not use a five-
second Zitadel lifetime for normal operation; it causes repeated redirects and
does not clear an already-loaded single-page application. After logout, reload
or reopen the protected UI so Traefik can run ForwardAuth again.

## Dependencies

- **Traefik** — TLS and routing
- **Zitadel** — OIDC issuer (start before oauth2-proxy)

The container uses `extra_hosts: zitadel.dss.localhost:host-gateway` so OIDC
discovery/token calls reach Traefik on the Docker host.
